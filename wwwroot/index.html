01THE PURPOSE

Keep the details.
Keep the story.

Game-related information can end up scattered across notes, screenshots, and old messages. Axes in Motion brings those details together in a small desktop tool that is quick to fill in and easy to revisit.

Each record is saved with a user name, a game, a save time, and the fields entered. The app shows the current values and earlier saves so a player can review the information without opening a new entry window.

03THE DATABASE

Clear records.
Useful queries.

The AxesInMotion database separates users, games, saved snapshots, and each snapshot’s field values. You can inspect the same saved data directly in SQL Server Management Studio.

Open the saved-data query ↗
SAMPLE QUERY
SELECT
    u.UserName,
    s.GameName,
    s.SavedAt,
    v.FieldName,
    v.FieldValue
FROM dbo.EntrySnapshots AS s
JOIN dbo.Users AS u ON u.UserId = s.UserId
JOIN dbo.EntryValues AS v ON v.SnapshotId = s.SnapshotId
ORDER BY s.SavedAt DESC;
↳ Run this in a query window connected to AxesInMotion.

04GETTING STARTED

Up and running
in four steps.

  1. 01
    Create the database

    Open AxesInMotion.sql in SSMS, connect to your local SQL Server, and execute it once.

  2. 02
    Start the API

    Run Start Server.cmd from the project folder. The default address is http://localhost:5080.

  3. 03
    Open the desktop app

    Run Axes in Motion in Visual Studio. Confirm the server status shows connected.

  4. 04
    Save and inspect

    Select a game, enter a user name and values, save, then open ViewSavedData.sql in SSMS.

i

SQL Server uses Windows authentication by default. The Windows account running the API needs permission to use the AxesInMotion database.
